# Common Beginner Mistakes

GitHub can be confusing when you are starting out. Understanding the difference between a few common terms can make the workflow easier.

## 1. Confusing Git and GitHub

Git and GitHub are related, but they are not the same thing.

Git is a version control system used to track changes.

GitHub is a platform where Git repositories can be stored and shared online.

## 2. Confusing Saving With Committing

Saving a file saves the changes you made to the file.

A commit records those changes in the repository's history.

They are different actions.

## 3. Forgetting Which Branch You Are On

Always check the branch selector before making a change.

You may accidentally make a change on the wrong branch if you do not check.

## 4. Making Changes Directly on Main

For changes that need to be reviewed before being added to the main project, create a separate branch first.

This keeps the main branch more organized.

## 5. Creating a Pull Request With the Wrong Branches

Before creating a pull request, check the base and compare branches.

Make sure the pull request is going into the branch you intended.

## 6. Not Reviewing Changes

Review your changes before committing and again before merging a pull request.

This helps catch mistakes and unwanted changes.

## 7. Using Unclear Commit Messages

Commit messages should explain what changed.

For example:

`Add beginner GitHub workflow`

is clearer than:

`Update`

## 8. Thinking a Pull Request and a Commit Are the Same Thing

A commit records changes.

A pull request proposes those changes for review and possible merging.

They are different parts of the workflow.
