# Reviewing and Merging a Pull Request

Merging a pull request adds the changes from one branch to another.

In this example, the changes will be merged from:

`add-github-workflow`

into:

`main`

## Step 1: Open the Pull Request

Open your repository on GitHub.

Select the **Pull requests** tab.

Select the pull request you created.

## Step 2: Review the Changes

Read the pull request title and description.

Review the changed files.

Check that:

* The correct files were changed.
* The information is correct.
* The formatting looks right.
* No unwanted changes were included.

## Step 3: Check for Merge Problems

GitHub will indicate whether the pull request can be merged.

If there are conflicts, they need to be resolved before the pull request can be merged.

## Step 4: Merge the Pull Request

When the pull request is ready, select the merge option provided by GitHub.

Confirm the merge when asked.

The changes from the working branch will now be added to `main`.

## Step 5: Check the Main Branch

Return to the repository.

Use the branch selector to open:

`main`

Open the files that were changed.

The merged changes should now be part of the main branch.

## Step 6: Delete the Branch

After the pull request has been merged, GitHub may provide an option to delete the branch.

The branch can be deleted when it is no longer needed.

## The Complete Workflow

The basic workflow is:

**Create a repository → Create a branch → Make a change → Commit the change → Create a pull request → Review the change → Merge the pull request**
